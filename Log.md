2. Зафиксированные решения
1. recipes и productDB остаются изменяемыми массивами. В исходной
   PWA эти каталоги редактируются во время работы. Нельзя замораживать
   записи или создавать независимые копии каталога в разных модулях.
2. collections в первый комплект не переносится. Это изменяемое
   состояние с несколькими UI-потребителями; его жизненный цикл нужно
   выделить отдельно.
3. Функции конфигурации приёмов пищи получают необходимые данные явно.
   Скрытые обращения к глобальным profile и diaryEntries не
   переносятся в domain-слой.
4. Репозитории получают объект storage извне. Доступ к
   window.localStorage должен оставаться на границе приложения, а не
   внутри domain-слоя.
5. Существующие ключи хранения сохраняются без переименования:
   - nutrition-diary-v1
   - nutrition-water-v1
   - nutrition-weight-history-v1
   - nutrition-measurement-history-v1
6. Формат сохранённых пользовательских массивов не меняется. Отдельная
   миграция данных для этого комплекта не требуется.
7. Утверждённая архитектура проекта не меняется: contracts, domain,
   application, infrastructure, ui.

5. Правила сохранения данных и истории
- Не удалять и не переименовывать старые ключи localStorage без
  отдельного решения и плана миграции.
- Не очищать и не перезаписывать пользовательские записи при
  подключении новых репозиториев.
- Не запускать одновременно старую и новую загрузку одного и того же
  состояния: должен существовать один источник истины.
- Перед переключением пути загрузки/сохранения проверить чтение
  существующих данных, запись, повторное чтение и поведение при
  повреждённом JSON.
- Историю изменений вести в этом файле новыми записями. Не заменять
  предыдущие записи сводным текстом.
- Архивы комплектов миграции сохранять отдельно, чтобы можно было
  восстановить состояние каждого этапа.

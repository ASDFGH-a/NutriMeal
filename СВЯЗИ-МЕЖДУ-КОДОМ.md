# Связи между частями кода

Здесь указаны фактические runtime-связи. Разделы, представленные только файлами и тестами, помечены отдельно от подключённых сценариев.

## Точки входа и композиция

```text
index.html
  -> iframe -> PWA_v60_code_blocks.html     # production runtime / референс

app-preview.html
  -> src/ui/app/standalone-entry.js         # новый runtime
      -> initializeCoreData(localStorage)
      -> createDiaryServices(localStorage)
      -> createWaterServices(localStorage)
      -> createCatalogServices()
      -> UI flows: meal-add, mass-entry, statistics, settings
      -> render diary/catalog/statistics/settings
```

`application-bootstrap.js` создаёт shell, overlay и `app-state`. Далее `standalone-entry.js` самостоятельно обрабатывает навигацию и рендер; `router/app-router.js` и `screens/screen-router.js` здесь не используются. Кнопки Planning/Profile и несколько действий истории тела отключаются.

## Активные сценарии нового runtime

| Сценарий | UI-вход и связи | Данные и побочные эффекты |
|---|---|---|
| Инициализация | `standalone-entry.js` → `initialize-core-data.js` → domain seed и repositories | Загружает каталог, дневник, воду, профиль, план, историю тела, наборы, тему и настройки карточек |
| Дневник | `standalone-entry.js` → `diary-presenter.js` / `diary-screen.js`; действия записи из `meal-add-flow.js` | `diary-services.js` → diary use cases → diary repository; CRUD и массовые записи сохраняются |
| Массовая запись | `mass-entry-flow.js` → `diaryServices.massEntry.preview/apply` | Mass-entry use case проверяет источник, даты и конфликты; apply сохраняет в diary repository |
| Вода | Обработчики дневника в `standalone-entry.js` | `water-services.js` → add/remove/restore use cases → water repository |
| Каталог | `meal-add-flow.js` → catalog cards/filters/editors | `catalog-services.js` → catalog use cases; products/recipes/collections меняются в памяти |
| Настройки карточек | `meal-add-flow.js` → callback из `standalone-entry.js` | `catalog-card-settings.repository.js` сохраняет `nutrition-catalog-card-settings` |
| Статистика | `statistics-flow.js` → `get-diary-statistics.js` и domain statistics | Читает переданное состояние дневника, воды, веса, замеров, профиля и наборов; отдельного statistics repository нет |
| Настройки и теория | `settings-flow.js` → settings/theory screens | Тема сохраняется через theme repository; справочные таблицы строятся из domain data |

Каталог фильтров и настройки отображения карточек находятся в `domain/catalog/` и infrastructure соответственно. Их UI подключён в preview; это не меняет in-memory характер продуктовых и рецептурных данных.

## Наличие модулей без подключения в preview

| Область | Существующие модули | Текущая граница |
|---|---|---|
| Планирование | `planning-services.js`, use cases плана/пресетов/наборов, repositories, экраны и `planning-modals.js` | `standalone-entry.js` не создаёт planning service и не регистрирует маршрут; пункт меню выключен |
| Профиль | profile domain/repository, `profile-screen.js`, `profile-modal.js` | Нет profile flow/маршрута в standalone; пункт меню выключен |
| Вес и замеры | `body-history-services.js`, use cases, repositories и `body-history-modals.js` | Сервис не создаётся в standalone; связанные действия дневника выключены |
| Маршрутизация | `app-router.js`, `screen-router.js` | Модули есть, но текущий entry обрабатывает переходы вручную |

Эти реализации и тесты не следует считать доказательством завершённого пользовательского сценария в новом runtime.

## Основные зависимости слоёв

| Участок | Откуда → куда | Назначение |
|---|---|---|
| Bootstrap | UI → application services и UI-модули | Сборка состояния и сценариев запуска |
| Services | Application services → use cases, repositories, contracts | Поставка зависимостей и сохранение результатов |
| Use cases | Application → domain и contracts | Выполнение команд с явными аргументами и зависимостями |
| Repositories | Infrastructure → storage и domain normalizers | Чтение/запись состояния |
| UI flows | UI → services/use cases и domain read helpers | Обработка событий и отображение результата |
| Domain | Domain → только domain/shared | Предметные расчёты без DOM и localStorage |

Исключения и незавершённые связи фиксируются явно: `initialize-core-data.js` — application service, который непосредственно собирает infrastructure repositories; `statistics-flow.js` вызывает statistics use case напрямую; текущая навигация не использует выделенные router modules.

## Legacy boundary

`index.html` продолжает открывать `PWA_v60_code_blocks.html`. Новый standalone runtime не заменяет legacy и пока не подключает все разделы. Переключение entry point должно оставаться последним этапом после завершения планирования, профиля, навигации и проверки целых пользовательских сценариев на визуальный и функциональный паритет.

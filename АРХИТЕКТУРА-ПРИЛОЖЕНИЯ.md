# Архитектура приложения NutriMeal

## Назначение и текущая граница миграции

Этот документ описывает фактическое состояние кода, а не только целевую схему.

Сейчас в репозитории существуют два запуска:

- `index.html` — production-точка входа; показывает `PWA_v60_code_blocks.html` через iframe. Это текущий рабочий runtime и визуально-функциональный референс.
- `app-preview.html` — отдельный запуск нового runtime из `src/ui/app/standalone-entry.js`. Он предназначен для интеграции и проверки перенесённых сценариев; production-точку входа пока не заменяет.

Новый runtime включает дневник, каталог, статистику и настройки. Разделы «Планирование» и «Профиль» в навигации пока выключены; действия истории веса и замеров в дневнике тоже недоступны. Наличие их моделей, use cases, экранов и модалок в `src/` не означает, что эти сценарии уже подключены к preview.

## Слои и обязанности

```text
app-preview.html
  -> UI composition root (standalone-entry.js)
      -> application services / use cases
          -> domain rules
          -> contracts
      -> infrastructure repositories -> localStorage
```

Это направление зависимостей — целевой принцип. Фактическая композиция пока не полностью централизована: `standalone-entry.js` создаёт сервисы и flows, а некоторые существующие модули маршрутизации ещё не подключены к нему.

### Contracts

`src/contracts/` задаёт формы команд и результатов, проверки границ и storage-порт. Контракты не содержат предметных расчётов.

### Domain

`src/domain/` содержит модели и правила без зависимости от DOM и хранилища: питание и пищевые ценности, дневник, каталог, наборы питания, план, профиль, вода, история тела, статистика, даты и фильтрация.

### Application

`src/application/usecases/` реализует отдельные операции. `src/application/services/` связывает сценарии с репозиториями и предоставляет runtime-устройству вызовы более высокого уровня. `initialize-core-data.js` загружает seed-данные и сохранённое состояние.

Граница фактического подключения важна:

- `diary-services.js`, `water-services.js`, `catalog-services.js` и `initialize-core-data.js` используются новым preview.
- `get-diary-statistics.js` вызывается `statistics-flow.js` напрямую.
- `planning-services.js` и `body-history-services.js` существуют, но `standalone-entry.js` их пока не создаёт.
- Данные продуктов, рецептов и подборок остаются в памяти; отдельные репозитории для них не добавлялись. В каталоге сохраняются только настройки карточек.

### Infrastructure

`src/infrastructure/persistence/` содержит адаптер хранения и репозитории. Репозитории сохраняют совместимые localStorage keys; доменные нормализаторы используются там, где это предусмотрено конкретным репозиторием.

### UI

`src/ui/` содержит каркас, экраны, модальные шаблоны, flows и форматирование. Новый runtime собирается в `standalone-entry.js`, но часть маршрутизации пока выполняется там же вручную: `app-state` используется для active page, однако `app-router.js` и `screen-router.js` в entry point не импортируются.

## Подключение сценариев в новом runtime

| Область | Что подключено в `app-preview.html` | Ограничение |
|---|---|---|
| Дневник | Просмотр по датам, добавление/изменение/замена/удаление записей, отмена удаления, вода, массовая запись | Вес и замеры в дневнике пока выключены |
| Каталог | Рецепты, продукты, подборки, фильтры, пользовательские категории/теги, настройки карточек | Продукты, рецепты и подборки не сохраняются между запусками |
| Статистика | Статистика питания и тела, периоды и детальные представления | Использует загруженное состояние; собственного statistics repository нет |
| Настройки | Тема и раздел теории | Остальные настройки и профиль не являются подключённым маршрутом |
| Планирование | Нет активного маршрута | Domain, services, repositories, use cases и UI-шаблоны есть, но preview их не собирает |
| Профиль / история тела | Нет активного маршрута | Модели, сервисы, репозитории и некоторые UI-модули есть, но preview их не собирает |

## Хранение данных

Подключённые репозитории используют следующие ключи:

| Данные | Ключ |
|---|---|
| Дневник | `nutrition-diary-v1` |
| Вода | `nutrition-water-v1` |
| Вес | `nutrition-weight-history-v1` |
| Замеры | `nutrition-measurement-history-v1` |
| Профиль | `nutrition-profile-v1` |
| План | `nutrition-plan-v2` |
| Пресеты плана | `nutrition-plan-presets-v1` |
| Наборы питания | `nutrition-sets-v1` |
| Активный набор | `nutrition-active-set-v1` |
| Тема | `nutrition-theme` |
| Настройки карточек каталога | `nutrition-catalog-card-settings` |

Список репозиториев и ключей не означает, что все соответствующие UI-сценарии включены в standalone runtime. Seed-каталог и состояние инициализируются `initialize-core-data.js`; продукты, рецепты и подборки после этого живут в памяти.

## Правила развития

1. Сохранять визуальное и функциональное поведение PWA v60; сравнивать законченные сценарии целиком, не считать наличие отдельных экранов завершённой миграцией.
2. Новую предметную логику размещать в domain/application, а не в обработчиках DOM.
3. Мутации проходить через use cases/services; работу с persistent storage — через repositories.
4. Не менять `index.html` и не удалять legacy runtime до интеграции всех разделов и проверки паритета.
5. Не вводить persistence для каталога без отдельного решения о требуемом поведении и совместимости.

## Проверка, зафиксированная при обновлении

Последний полный прогон, отражённый в текущем рабочем плане: `npm test` — 170/170. Последний завершённый интеграционный срез нового preview — каталог: фильтры, категории/теги и настройки карточек. Планирование, профиль и production-переключение этим результатом не закрываются.

# Архитектура приложения NutriMeal

## Назначение документа

Документ фиксирует фактическую архитектуру проекта на момент миграции с PWA v60 на многослойную структуру.

## Текущий результат

Проект находится в переходном состоянии:

- перенос доменных сущностей, use cases и persistence выполняется в `src/`;
- публичные границы модулей описаны в `src/contracts/`;
- новые экраны и общие UI-компоненты появляются в `src/ui/`;
- старый `PWA_v60_code_blocks.html` сохраняется как временный совместимый runtime;
- `index.html` пока подключает приложение через iframe старого документа;
- удалять или заменять legacy-код можно только после интеграционной проверки полного экрана.

## Слои

```text
UI
  -> Application
  -> Domain
  <- Infrastructure
       |
  Contracts / Ports
```

### Contracts

`src/contracts/` содержит:

- объектные формы запросов и результатов;
- порты storage/repositories;
- runtime-проверки boundary-контрактов;
- узкие проверки допустимых источников, дат, массивов и форматов.

Contracts не должны содержать расчёты предметной области.

Основные контракты:

| Модуль | Назначение |
|---|---|
| `storage.contract.js` | Storage и repository-порты |
| `body-history.contract.js` | История веса и замеров |
| `catalog.contract.js` | Коллекции, продукты, рецепты |
| `diary.contract.js` | Мутации записей дневника |
| `mass-entry.contract.js` | Массовая запись и её preview/result |
| `nutrition-set.contract.js` | Наборы питания и активный набор |
| `planning.contract.js` | Расчёт плана и пресеты |
| `statistics.contract.js` | Запрос и результат статистики |
| `water.contract.js` | Записи воды |

### Domain

`src/domain/` содержит чистые сущности и предметные правила:

- нормализацию данных;
- расчёт КБЖУ;
- расчёт профиля и плановых целей;
- дневник и историю тела;
- наборы питания;
- статистику;
- общие даты и фильтры.

Domain не должен знать о DOM, `localStorage`, HTML и UI-событиях.

### Application

`src/application/usecases/` описывает операции прикладного уровня:

- создание и редактирование записей;
- удаление и восстановление;
- сохранение пресетов;
- статистический запрос;
- применение сценария массовой записи;
- изменение истории веса и замеров.

Каждый use case принимает готовые данные и порты/репозитории через явные аргументы.

`initialize-core-data.js` является композиционным application service: собирает стартовые данные и репозитории из infrastructure/domain.

### Infrastructure

`src/infrastructure/persistence/` отвечает за сохранение.

- `storage.js` адаптирует array/object хранилище и проверяет storage/repository-порты.
- `repositories/` используют stable localStorage-ключи и нормализаторы домена.
- ключи хранилища сохраняются совместимо со старым приложением.

### UI

`src/ui/` разделён на:

- `app/` — bootstrap и композиция приложения;
- `components/` — каркас страницы и overlay-хосты;
- `router/` — маршрутизация по внутренним экранам;
- `state/` — активный экран;
- `screens/` — разметка экранов;
- `modals/` — разметка модальных окон;
- `utils/` — форматирование и escaping.

## Основные потоки данных

### Запуск приложения

```text
index.html
  -> PWA_v60_code_blocks.html
  -> bootstrap
  -> app-shell
  -> screen router
  -> active screen
```

### Изменение профиля

```text
UI modal
  -> profile input
  -> profile use case/repository
  -> normalizeProfileData
  -> localStorage
  -> rerender
```

Вес и рост синхронизируются через отдельные use cases истории.

### Запись в дневник

```text
Diary UI
  -> diary use case
  -> diary contract
  -> diary-entry/domain rules
  -> diary repository
  -> localStorage
```

### Массовая запись

```text
UI preview command
  -> mass-entry use case
  -> domain date/collision/source rules
  -> diary mutation contract
  -> diary repository
```

### Статистика

```text
UI period state
  -> get-diary-statistics
  -> diary-statistics domain calculations
  -> statistics contract
  -> UI statistics cards
```

| Область | Domain | Application | Infrastructure | Contracts | UI |
|---|---|---|---|---|---|
| Каталог | Да | Да | Частично | Да | Legacy |
| Профиль и план | Да | Да | Да | Да | Частично |
| Наборы питания | Да | Да | Да | Да | Legacy |
| Дневник | Да | Да | Да | Да | Частично |
| Массовая запись | Да | Да | Да | Да | Legacy |
| Статистика | Да | Да | Нет отдельного порта | Да | Частично |

| Навигация/состояние | Нет | Нет | Нет | Нет | Да |

## Правила расширения

1. HTML и обработчики не являются источником предметных правил.
2. Новые use cases принимают явные команды и репозитории.
3. Формы и модалки работают через представления `src/ui/`, но мутации идут через application.
4. localStorage доступен только через infrastructure/repository или явно переданный storage-порт.
5. Legacy-файл не расширяется; новые функции извлекаются в соответствующие слои.
6. Любая новая логика получает тесты в `tests/`.

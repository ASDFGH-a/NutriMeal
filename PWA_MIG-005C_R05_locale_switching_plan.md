# PWA v60 — MIG-005C: сценарий переключения и восстановления локали

**Статус:** план зафиксирован до реализации. Код этого этапа пока не добавлялся.

## 1. Цель

Подготовить независимый сценарий выбора RU/EN и восстановления выбранного языка при запуске приложения. Сохранить совместимость с ключом `nutrition-locale` и не затрагивать пользовательские данные.

## 2. Подтверждённые факты исходника v60

Источник: `PWA_v60_code_blocks(1).html`, SHA-256 `53bf58ff10c733ca15155d552df2e452a9dc3f2711c24169da5ac27637e43648`.

- В блоке локализации (строки 1267–1335) `appLocale` инициализируется значением `'ru'`.
- Старый `setAppLocale(next)` проверяет `I18N_LOCALES[next]`, присваивает `appLocale`, записывает значение в `localStorage` под ключом `nutrition-locale`, обновляет `document.documentElement.lang` и вызывает `setPage(activePage)`.
- В проверенном полном HTML ключ `nutrition-locale` встречается только в операции записи; чтение сохранённого значения при запуске не обнаружено.
- Страница настроек (`renderSettings()`, начиная со строки 3138) содержит блоки «Внешний вид» и «Данные приложения», но переключателя языка нет.
- В конце скрипта вызывается `render()`; до этого вызова восстановление локали из хранилища не выполняется.
- В текущем `render()` при `appLocale !== 'ru'` вызывается `applyI18n(page)`. Старый `applyI18n` зависит от прежнего механизма перевода, который обращается к отсутствующим в исходном HTML `UI_TRANSLATIONS` и `UI_PHRASES`.
- `setPage()` обновляет заголовок/подзаголовок и вызывает `render()`. `titles` и DOM-узел `page` остаются на UI-границе и не переносятся в domain.

## 3. Контракт локали

- Разрешённые значения: `ru`, `en`.
- Значение по умолчанию: `ru`.
- Ключ хранения: строго `nutrition-locale`.
- Отсутствующее, пустое, повреждённое или неподдерживаемое значение при чтении означает `ru`.
- Попытка установить неподдерживаемую локаль отклоняется; текущее состояние и сохранённое значение не должны портиться.
- Ошибка доступа к хранилищу не должна ломать запуск или переключение в текущей сессии.
- Пользовательские данные (продукты, рецепты, категории, заметки, профиль, дневник, планы и наборы) не переводятся и не изменяются.

## 4. Разделение ответственности и целевые файлы

### Domain

`src/domain/localization/locale-data.js` остаётся владельцем списка локалей. При необходимости добавить чистую проверку допустимого кода локали — без `localStorage`, DOM и глобального состояния.

### Application

`src/application/localization/locale-preferences.js` — сценарии:
- разрешение начальной локали из значения хранилища с fallback на `ru`;
- проверка и нормализация запрошенной локали;
- координация выбора локали через явно переданные зависимости.

Application не обращается напрямую к `window`, `document` или `localStorage`.

### Infrastructure

`src/infrastructure/persistence/repositories/locale-preferences.repository.js` — чтение и запись единственного ключа `nutrition-locale` через переданный storage-объект. Не создавать новый ключ и не менять формат значения.

### UI

`src/ui/localization/locale-ui.js` — UI-адаптер для применения выбранного кода к `document.documentElement.lang` и вызова переданной функции перерисовки. DOM не импортируется в domain/application.

Размещение реального переключателя в `renderSettings()` и подключение к стартовой последовательности исходного HTML фиксируются как отдельная интеграционная работа после проверки модулей. На этом этапе исходный HTML не переписывается.

## 5. Публичные контракты (проект реализации)

- `createLocalePreferencesRepository(storage, { key })`: `load()` возвращает сохранённое сырое значение или `null`; `save(locale)` сохраняет строковый код. Ошибки чтения/записи обрабатываются предсказуемо и не маскируются под другую локаль.
- `resolveInitialLocale(savedLocale, supportedLocales, fallbackLocale)`: возвращает допустимую локаль либо fallback.
- `createLocalePreferences({ repository, supportedLocales, fallbackLocale })`: `loadInitialLocale()` восстанавливает допустимое значение; `setLocale(locale)` отклоняет неподдерживаемые значения, сохраняет допустимое и возвращает результат без доступа к DOM.
- `applyLocaleToDocument(locale, { document, rerender })`: устанавливает `document.documentElement.lang` и вызывает переданную функцию обновления интерфейса. Зависимости передаются явно для тестируемости.

Точные имена и shape результата уточняются в коде до реализации тестов, но перечисленные инварианты обязательны.

## 6. Тесты

- `ru` и `en` принимаются; другие коды отклоняются.
- `null`, пустая строка и неизвестный сохранённый код дают `ru`.
- Сохранённый `en` восстанавливается как `en`.
- `setLocale('fr')` не меняет активное значение и не перезаписывает корректную сохранённую настройку.
- Репозиторий читает/пишет только `nutrition-locale`.
- Ошибка чтения даёт безопасный fallback `ru`; ошибка записи не ломает активную сессию.
- UI-адаптер меняет только `document.documentElement.lang` и вызывает переданный rerender ровно один раз.
- Ни один модуль domain/application не обращается к DOM или `localStorage` напрямую.
- Все прежние тесты R01–R05-B2 продолжают проходить.

## 7. Что не входит в этот этап

- Полная интеграция нового механизма в исходный HTML.
- Реальное добавление переключателя в `renderSettings()`.
- Перевод всех динамических шаблонов и всех экранов.
- Удаление старых `translateText`, `applyI18n`, `setAppLocale` из HTML.
- Изменение любых пользовательских данных или других ключей localStorage.
- Заявление о браузерной проверке без запуска приложения в браузере.

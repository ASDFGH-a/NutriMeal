# PWA v60 — MIG-005B: локализация RU / EN

**Статус:** решение по набору языков принято; план зафиксирован до реализации.

## 1. Принятое решение

Поддерживаются только два языка:
- `ru` — русский, язык по умолчанию;
- `en` — английский.

Испанский и французский исключаются из публичного списка языков и из новых локализационных контрактов. Не создавать заглушки для других языков.

## 2. Цель этапа

Завершить основу R05 так, чтобы интерфейс приложения мог полноценно переключаться между русским и английским, а выбранный язык сохранялся между перезапусками.

Пользовательские данные не переводятся автоматически: названия продуктов и рецептов, заметки, пользовательские категории, ингредиенты, значения профиля и содержимое дневника сохраняются и отображаются в исходном виде.

## 3. Что известно по исходнику

- `appLocale` изначально равен `ru`.
- `localeTags()` использует `ru-RU` для русского и код локали для остальных языков.
- `trMeal()` переводит названия приёмов пищи.
- `translateText()` обращается к `UI_TRANSLATIONS` и `UI_PHRASES`, которых нет в полном исходном HTML.
- `applyI18n()` переводит текстовые узлы и атрибуты `title`, `aria-label`, `placeholder`.
- `setAppLocale()` записывает выбранный язык в `nutrition-locale`, меняет `document.documentElement.lang` и перерисовывает текущую страницу.
- Исходный код не восстанавливает сохранённую локаль при запуске.

## 4. План реализации

### R05-B1 — контракты и данные

- Ограничить `I18N_LOCALES` значениями `ru` и `en`.
- Оставить русские и английские месяцы, короткие дни недели и названия приёмов пищи.
- Определить единый контракт словаря UI: ключ — точная русская исходная строка; значение — английский перевод.
- Для отсутствующего перевода использовать исходную строку, не падать и не подменять пользовательский текст.

### R05-B2 — инвентаризация и словарь интерфейса

- Извлечь статические подписи интерфейса из исходного HTML и шаблонов.
- Разделить строки интерфейса и динамические пользовательские данные.
- Переводить полные подписи и устойчивые фразы; не применять опасные глобальные замены коротких слов внутри пользовательского текста.
- Сохранить форматирование, числа, единицы измерения, HTML-разметку и значения атрибутов.
- Не считать этап завершённым, пока не покрыты все основные экраны: дневник, рецепты, планирование, статистика, профиль, настройки, модальные окна и уведомления.

### R05-B3 — сценарий переключения языка

- Проверять выбранный код по разрешённому списку `ru` / `en`.
- Сохранять язык под прежним ключом `nutrition-locale`.
- При запуске восстанавливать сохранённый язык; при отсутствующем или некорректном значении использовать `ru`.
- Обновлять `document.documentElement.lang`.
- Перерисовывать текущую страницу после переключения.
- Переключатель языка должен показывать только русский и английский.

### R05-B4 — тесты

- Только `ru` и `en` доступны.
- Русский — fallback по умолчанию.
- Английский переводится по точному ключу.
- Неизвестные строки возвращаются без изменений.
- Неизвестный код языка отклоняется и не портит сохранённую настройку.
- Сохранённый язык восстанавливается при запуске.
- Пользовательские данные не переводятся и не мутируются.
- Все прежние тесты R01–R05-A продолжают проходить.

## 5. Предлагаемое разделение по архитектуре

- `domain/localization`: поддерживаемые локали, справочники и чистые функции разрешения перевода.
- `application/localization`: сценарии выбора и восстановления языка, без прямой зависимости от DOM.
- `infrastructure/persistence`: адаптер чтения/записи `nutrition-locale`.
- `ui/localization`: применение перевода к DOM и переключатель языка.
- `tests`: тесты каждого контракта и интеграционные проверки локализации.

## 6. Границы и запреты

- Не менять содержимое дневника, рецептов, профиля, планов и наборов питания.
- Не переводить пользовательский контент автоматически.
- Не менять ключ `nutrition-locale`.
- Не переносить `titles` и DOM-узел `page` в domain.
- Не удалять старый UI-код до готовности и проверки нового.
- Не заявлять браузерную интеграцию, пока она не проверена в реальном приложении.

## 7. Критерии завершения

R05 считается завершённым только после реализации RU/EN словаря, сценария переключения и восстановления языка, подключения к UI и проверки основных экранов. Изолированные справочники или успешные unit-тесты сами по себе не означают завершение R05.


## 5. Фактический статус после R05-B2

**R05-B1:** выполнен — справочники локалей ограничены `ru` и `en`.

**R05-B2:** выполнен в ограниченном объёме — создан словарь из 227 точных UI-фраз, присутствующих в исходном HTML, и чистая функция точного перевода. Словарь не использует подстрочные замены: неизвестные строки и пользовательские данные сохраняются без изменений.

**Не входит в R05-B2:** перевод всех динамических шаблонов, DOM-обход `applyI18n`, переключение языка `setAppLocale`, восстановление `nutrition-locale` при запуске, интеграция в HTML и браузерная регрессия. Эти задачи остаются для следующих подэтапов.

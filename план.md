# План переноса NutriMeal на целевую архитектуру

## Статус плана

Есть два запуска нового runtime:

- `index.html` теперь запускает production runtime напрямую через `standalone-entry.js`, без iframe.
- `app-preview.html` остаётся отдельной точкой интеграционной проверки. `PWA_v60_code_blocks.html` сохранён как legacy-референс и fallback.

**Основная миграция завершена:** все исходные пункты U1.1–U1.4 и E1.1–E1.3 выполнены. Production использует новый runtime; application services получают repositories из composition root. Последние уточнения domain/UI-границы завершены для каталожных фильтров и подбора рецептов по пищевым группам. Обязательного незакрытого пункта исходного плана нет.

Данные каталога пока не сохраняются после перезапуска, импорт/экспорт не реализован, а legacy-файл оставлен fallback. Эти темы вынесены в отдельные решения ниже и не блокируют завершение миграции.

**Последний полный результат тестов:** `npm test` — 202/202. Интеграционно проверены сценарии планирования и подбора рецептов по пищевой группе, профиля, дневниковые CRUD/вода, массовая запись из библиотеки с отображением в дневнике и статистике после reload, CRUD каталога, фильтры, переключение выбранных значений, создание пользовательского тега с автоматическим выбором, переименование категорий и значений, валидации, тема и теория. Архитектурные тесты фиксируют направления зависимостей между слоями, запрещают прямой доступ domain/application к browser APIs и ограничивают доступ UI к persistence composition root. На ширине 390 px полностью пройден мобильный массовый сценарий: выбор даты → библиотека → предпросмотр → запись продукта; запись появилась в localStorage на выбранную дату, после чего исходное хранилище восстановлено. В production `index.html` подтверждены отсутствие iframe, работа навигации и сохранение воды после reload. Все шесть маршрутов работают на 390 px без горизонтального переполнения; desktop сохраняет боковую навигацию. Ошибок JavaScript при переходах не обнаружено.

1. **U1.1 — стабилизировать подключённое планирование.**

Проверены обновление панели при переключении периода и мобильная ширина. Тесты модалок проверяют значения и безопасный вывод данных.

## Последующие решения (не входят в завершённую миграцию)

| Тема | Статус | Что требуется для планирования |
|---|---|---|
| Постоянное хранение продуктов, рецептов и подборок | Отложено; сейчас данные каталога in-memory | Определить ожидаемое поведение, формат хранения, миграцию и совместимость прежде чем добавлять repositories/storage key |
| Импорт/экспорт каталога | Не реализовано; исходный интерфейс помечает функцию как «В разработке» | Определить формат, включаемые данные, правила валидации и сценарии восстановления |
| Удаление `PWA_v60_code_blocks.html` | Отложено; файл остаётся fallback и референсом | Отдельно согласовать отказ от fallback и выполнить финальное сравнение ключевых сценариев |
| Дальнейшая полировка domain/UI-границ | Текущая необязательная работа, без известного блокирующего списка | Продолжать только когда найден конкретный предметный расчёт/преобразование в UI; отображение и координацию оставлять в UI |

Ни одна из этих тем не является обязательным незавершённым пунктом U1/E1. Для первых трёх сначала нужно отдельное решение по требованиям; не добавлять persistence или удалять legacy по предположению.

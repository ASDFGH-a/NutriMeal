# R05-B3 — Переключение языка и восстановление сохранённой локали

**Статус:** план этапа, до реализации  
**Исходная версия:** PWA v60  
**Предыдущий этап:** R05-B2 (справочник UI-переводов и функции перевода)  
**Поддерживаемые локали:** `ru`, `en`

## 1. Цель

Реализовать жизненный цикл локали: безопасно прочитать сохранённый выбор при запуске, использовать русский как fallback, сохранять выбор пользователя и обновлять интерфейс при переключении языка.

Этап не должен менять бизнес-логику приложения, пользовательские данные, ключи хранения данных или структуру других модулей.

## 2. Подтверждённое поведение исходника v60

По проверке исходного HTML:

- `appLocale` инициализируется значением `ru`.
- `I18N_LOCALES` в исходнике содержит четыре языка (`ru`, `en`, `es`, `fr`); целевой контракт миграции ограничивает набор `ru` и `en`.
- `setAppLocale(next)` проверяет `I18N_LOCALES`, меняет `appLocale`, записывает `nutrition-locale`, обновляет `document.documentElement.lang`, подписи навигации и `quick-add`, затем вызывает `setPage(activePage)`.
- При запуске нет чтения `nutrition-locale`.
- В конце скрипта вызывается `render()`.
- `render()` вызывает `applyI18n(page)` только для английского языка.
- `applyI18n()` изменяет текстовые узлы и атрибуты DOM на месте. При последующем переключении на русский исходные русские значения из уже изменённого DOM сами по себе не восстанавливаются.
- `setPage()` обновляет заголовок и подзаголовок страницы и вызывает `render()`.

## 3. Контракты

### 3.1 Локали

- Разрешённые значения: `ru`, `en`.
- Значение по умолчанию: `ru`.
- Любое отсутствующее, неизвестное или некорректное сохранённое значение нормализуется в `ru`.
- `document.documentElement.lang` должен соответствовать активной локали (`ru` или `en`).

### 3.2 Хранилище

- Единственный ключ: `nutrition-locale`.
- Формат значения: строка `ru` или `en`.
- Не создавать новый ключ и не переносить значение в другой storage.
- Ошибка чтения/записи `localStorage` не должна блокировать запуск или переключение интерфейса.
- При недоступном хранилище приложение работает с локалью `ru` до явного переключения в текущей сессии.

### 3.3 Переключение

- Недопустимое значение не меняет текущую локаль и не вызывает перерисовку.
- При успешном переключении обновляются локаль форматирования, системный `lang`, навигация, заголовки и содержимое активной страницы.
- Повторный выбор уже активной локали не должен приводить к повреждению DOM или лишним побочным эффектам.
- Пользовательские данные (названия продуктов/рецептов, заметки, категории, записи дневника и значения профиля) не переводятся автоматически.

### 3.4 Обратимость отображения

Переключение `ru → en → ru` должно возвращать интерфейс к исходным русским UI-строкам. Нельзя пытаться восстановить русский интерфейс простым повторным запуском `translateText()` поверх уже переведённого DOM.

Предпочтительный контракт: переводимые UI-строки должны формироваться из исходных значений при рендере либо иметь надёжный механизм восстановления исходного текста и атрибутов. Не сохранять и не переписывать пользовательские значения ради локализации.

## 4. Предлагаемое распределение ответственности

Распределение по утверждённым слоям; точные имена файлов и экспортов сверить с фактической картой проекта перед реализацией:

- **domain/localization:** список допустимых локалей и нормализация значения локали.
- **application/localization:** сценарии получения начальной локали и смены локали.
- **infrastructure/persistence:** адаптер чтения/записи ключа `nutrition-locale` с обработкой ошибок.
- **ui/localization:** применение активной локали к документу и запуск обновления интерфейса.
- **tests:** unit-тесты нормализации и storage; тесты сценариев и DOM-интеграции отдельно от unit-тестов.

Не создавать параллельные репозитории локали, если в комплекте R05-B1/B2 уже существует подходящий контракт или storage adapter.

## 5. Последовательность реализации

1. Сверить фактические `FILE_MAP.md`, `CONTRACTS.md`, R05-B1/B2 и существующие storage-адаптеры.
2. Зафиксировать точные контракты и зависимости в документации этапа.
3. Реализовать нормализацию локали и безопасное чтение/запись `nutrition-locale`.
4. Реализовать восстановление локали до первого `render()`.
5. Реализовать переключение с обновлением документа и активной страницы.
6. Устранить необратимое изменение DOM при `applyI18n`; выбрать способ восстановления исходных UI-строк, совместимый с существующим рендерингом.
7. Добавить тесты и выполнить проверки.
8. Добавить запись в конец `PWA_MIGRATION_LOG.md`, не переписывая старые записи; обновить `FILE_MAP.md` и `CONTRACTS.md`.
9. Собрать новый кумулятивный архив, не заменяя архивы предыдущих этапов.

## 6. Критерии приёмки

- [ ] При отсутствии `nutrition-locale` стартовая локаль — `ru`.
- [ ] Сохранённое `en` восстанавливается до первого отображения интерфейса.
- [ ] Сохранённое `ru` восстанавливается корректно.
- [ ] Неизвестное значение приводит к `ru`.
- [ ] Ошибки `localStorage.getItem` и `setItem` не ломают приложение.
- [ ] Переключение `ru → en` обновляет страницу и `document.documentElement.lang`.
- [ ] Переключение `en → ru` полностью возвращает русские UI-строки.
- [ ] Повторное переключение не накапливает искажения текста и атрибутов.
- [ ] Пользовательские данные не переводятся и не изменяются.
- [ ] Существующие ключи localStorage и их форматы не затронуты.
- [ ] Unit-тесты, тесты сценариев и интеграционные проверки указаны раздельно.

## 7. Границы этапа

В R05-B3 не входит полный перевод новых UI-строк, отсутствующих в словаре R05-B2, и не входит ручной перевод пользовательского контента. Не переписывать весь UI и не менять бизнес-логику. Исходный HTML v60 остаётся неизменным до отдельного согласованного этапа интеграции.

## 8. Проверки, которые нельзя подменять

Прохождение unit-тестов не означает, что переключение проверено в браузере. В отчёте отдельно указывать:

- unit-тесты;
- тесты application-сценариев;
- DOM/integration-тесты;
- ручную браузерную проверку, если она действительно выполнена.
